The Problem

AI agents with unsupervised system access

AI coding assistants and autonomous agents are already executing commands on production systems. Without guardrails, every AI action is a liability — legally, financially, and operationally.

  • RISK AI agent runs rm -rf / or drops a database. No policy prevented it. No audit trail exists.
  • RISK Prompt injection causes an AI to exfiltrate credentials. No detection, no containment, no evidence.
  • RISK EU AI Act requires human oversight and traceability for high-risk AI. Your current stack has neither.
  • RISK AI causes operational damage. Without audit logs or policy evidence, the organization cannot demonstrate due diligence. Regulatory penalties and civil liability follow.
  • RISK Multiple AI agents across teams, each with ad-hoc access. No central visibility, no unified policy, no kill switch.
The Solution

One binary between AI and everything

RavenFabric sits between AI agents and the systems they access. Every action is policy-checked, cryptographically authenticated, and audit-logged. Deny-by-default. The AI can only do what the policy explicitly permits. 

AI Agent (Claude, GPT, Cursor, Aider, custom)
    │
    ▼

    ├── Policy check: Is this command allowed? For this agent? Right now?
    ├── Prompt injection detection: Heuristics + scoring + auto-containment
    ├── Human approval: Require sign-off for sensitive operations
    ├── Audit log: Structured JSON-lines, every action, immutable

Target system is untouched. Agent is a single static binary. No runtime deps.
🛡

Deny-by-Default Policy

Nothing executes unless explicitly permitted. YAML-defined rules for commands, filesystem paths, and resources. Immutable deny lists for destructive operations.

📜

Full Audit Trail

Every AI action produces a structured JSON log entry: who, what, when, the requesting prompt/tool call, policy decision, and duration. Append-only log written locally on the agent (survives relay outages) with optional centralized aggregation for fleet-wide compliance reporting. Forensic-grade evidence for incident reconstruction and regulatory review.

🤖

Works With Every AI Agent

Native MCP (Model Context Protocol) server for direct integration with MCP-compatible clients: Claude Desktop, Claude Code, Cursor, Windsurf, Aider. For AI platforms that use other integration patterns (GitHub Copilot, OpenAI Agents, LangChain, CrewAI, AutoGen), RavenFabric exposes protocol-agnostic skill definitions and a standard CLI/API surface. MCP is an evolving standard — RavenFabric tracks it closely and hedges with protocol-agnostic interfaces, so the security layer works regardless of which AI integration standard wins.

🧠

Prompt Injection Defense

Detects base64 payloads, unicode homoglyphs, eval patterns, and known injection markers. Suspicion scoring per session with automatic capability reduction.

👫

Human-in-the-Loop

Configurable approval workflows for sensitive operations. SHA-256 bound, one-time-use, 30-minute TTL. The AI requests, a human approves, the system executes.

🔍

Behavioral Anomaly Detection

Per-identity baselines with threshold-based alerting on command velocity, path novelty, timing patterns, and escalation attempts. Auto-containment when configurable thresholds are breached. Thresholds are tunable per tenant with sensible defaults. No black-box ML — deterministic rules that auditors can inspect, verify, and adjust to minimize false positives.

🧩

Composable MCP Tools

AI agents discover and invoke operational actions via MCP tool definitions. Each tool is policy-gated: the agent decides what to do; RavenFabric decides whether it’s allowed, executes it safely, and logs every detail.

🔧

Ready-Made Tool Set

Ships with production-ready tools: command execution, file operations, system metrics, health checks, service management, and desired-state convergence. Extend with custom policy definitions in YAML.

🔗

Secure API Proxy & Tunnels

Proxy HTTP and TCP traffic through RavenFabric agents to private services — no VPN, no exposed ports, no firewall changes. Policy controls which hosts, ports, HTTP methods, and path patterns are reachable. Every connection and every HTTP request is audited. Includes local port forwarding, remote port forwarding, and SOCKS5 dynamic proxy. Replaces Tailscale Funnel, Cloudflare Tunnel, and SSH port-forwarding.

🔑

Secret Management & Fleet Distribution

Sealed secret store on each agent. Push secrets to any agent or entire fleet over the encrypted channel — the value is encrypted at rest and never logged in plaintext. Zero-downtime rotation: the old secret remains valid for a configurable grace period while the new value propagates. Pull from enterprise backends without storing credentials in policy files: HashiCorp Vault, AWS Secrets Manager, Azure Key Vault, GCP Secret Manager, and generic HTTP endpoints. Key material is zeroed from memory on release.

📊

SIEM Integration & Real-Time Alerting

Forward audit events in real time to Splunk HEC, Elasticsearch, Datadog, or any syslog target (RFC 5424). Export in the format your security team already uses: CEF, LEEF, OCSF, or native structured JSON-lines. Define alert rules that fire on policy denials, anomaly scores, session events, or custom patterns. Route alerts to Slack, PagerDuty, OpsGenie, or a generic webhook. Buffered delivery with deduplication ensures no events are dropped during network interruptions.

📦

Bulk File Transfer

Transfer single files or recursive directory trees between any two points in the mesh: rf cp over the encrypted channel. Automatic compression, chunked transfer, progress reporting, and SHA-256 integrity verification on arrival. Obeys the same path policies as all other operations — transfer attempts outside allowed paths are blocked and logged.

Technical Architecture

Questions technical evaluators will ask

We have answers. These are the details that matter in a due diligence conversation.

Key Rotation & Trust Model

Key Rotation Elliptic curve key pairs with automated rotation via the enrollment subsystem. No certificate authority. No expiry-date tracking. Key material is cryptographically zeroed from memory after use.
Binary Trust Single static executable. Binary integrity verified via published checksums. The agent trusts only its configured controller public key — no implicit trust of network, DNS, or CA infrastructure.
Trust Bootstrap Secure enrollment protocol: single-use, time-limited, hash-verified. After initial enrollment, every connection is mutually authenticated. No trust-on-first-use. No leap-of-faith. Details available in technical deep-dive.

Deployment & High Availability

HA Model Relay is stateless — run multiple behind a load balancer. Agents reconnect with exponential backoff + jitter. No session state on the relay means any relay instance can serve any agent. Policy distribution is conflict-free and tolerates network partitions (no single point of failure for policy updates).
Scaling Relay is lightweight and designed for high concurrency (benchmarks forthcoming with design partner deployments). Horizontal scaling by adding relay instances. Agent-side: single static binary, < 10 MB RAM idle. No database required for core operation.

IAM Integration

Current Identity is cryptographic: each agent and client has a Curve25519 key pair. RBAC policies bind permissions to caller identity (public key fingerprint). Policy files define which identities can execute which commands on which systems.
Roadmap OIDC/SAML bridge planned for enterprise IAM (Entra ID, Okta, Google Workspace). Maps external identity tokens to RavenFabric key identities. The bridge issues scoped, time-limited credentials — the policy engine remains the enforcement point regardless of identity source.

Policy Language

vs. Rego YAML policy definitions, not a general-purpose policy language. Intentionally domain-specific: commands, filesystem paths, resources, timeouts. YAML is auditable by non-developers, version-controllable, and diff-friendly. When a regulator asks “show me your policy,” anyone can read the answer.
Enforcement Command-level and path-level controls with traversal protection. Immutable deny lists that cannot be overridden. Resource limits enforced at the execution boundary. Integrated injection detection during policy evaluation. Full specification available under NDA.

Testing & Code Quality

1,432 Tests Mix of unit, integration, and end-to-end tests. Security-critical paths (policy evaluation, crypto handshake, enrollment validation, injection detection, proxy policy enforcement) have both positive and negative test coverage. Serialization types have roundtrip tests. Error paths are tested, not just happy paths.
Why Not More? Rust’s type system eliminates entire categories of bugs at compile time: null references, data races, use-after-free, buffer overflows. Code that would require runtime tests in Go or Python is caught by the compiler in Rust. The test suite focuses on logic and behavior, not type safety — the compiler already handles that. #[forbid(unsafe_code)] is enforced workspace-wide.
CI Pipeline Every commit runs the full test suite, Clippy (zero warnings policy), format check, MSRV verification, cross-compilation for 5 targets, and CodeQL security analysis. Coverage is tracked. No merge without green CI.
